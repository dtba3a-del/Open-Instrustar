# `ictpu/` — коннектор пути A (InstruStar `vdso.dll`)

Отдельное дерево исходников, отдельный каталог сборки, имя цели с
префиксом `I`. Разделение — не аккуратность, а требование
`docs/ACCESS_PATHS.md`: **путь A** (вендорская библиотека, постоянная
прошивка, драйвер вендора) и **путь B** (fx2lafw, прошивка в оперативку,
Zadig) — два состояния одного железа, а не два режима одной программы.
Общий каталог сборки склеил бы их объектными файлами.

```bash
cmake -S ictpu -B build-ictpu
cmake --build build-ictpu
ctest --test-dir build-ictpu --output-on-failure
```

Проект самостоятельный: корневой `CMakeLists.txt` его не подключает.
Библиотека `ICtPU` от Qt не зависит; зависят только тесты.

**GUI CtPU этим деревом не меняется.**

| файл | что делает |
|---|---|
| `src/ivdsoapi.h` | форма чужого API: **все 73 экспорта**, имена вендорские |
| `src/ivdsounits.{h,cpp}` | пересчёт единиц; единственное место, где живёт ×1000 |
| `src/ivdsosession.{h,cpp}` | порядок вызовов как автомат состояний |
| `src/ivdsoloader.{h,cpp}` | `LoadLibrary`/`GetProcAddress`; единственный файл, знающий про Windows |
| `tests/Itest_ivdsounits.cpp` | 21 проверка пересчёта |
| `tests/Itest_ivdsosession.cpp` | 41 проверка порядка вызовов, генератора и ввода-вывода |

Прибора и `vdso.dll` для прогона тестов **не нужно**: всё, что выше
загрузчика, работает через `IVdso::Api`, а в тестах его реализует
поддельный ISDS205B. Под Linux загрузчик собирается как честный отказ —
пути A на других системах нет.

Разбор, единицы, три запрета пути A, порядок вызовов и список замеров,
без которых нельзя подключать конвейер, — **`docs/INSTRUSTAR-CONNECTOR.md`**.
